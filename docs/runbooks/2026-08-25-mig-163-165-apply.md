# Migration 163–165 production runbook

Amaç: `questions` tablosunda PostgREST/API rolüyle doğrudan yazmayı kapatmak ve
revizyon kazanımlarını aktif, tam ve birebir game/category/exam müfredat yoluna
bağlamak.

## Güvenli sıra

1. Uygulama PR'ını deploy et. Yeni kod, governance bayrağı kapalıysa eski DML'e
   dönmez; 503 ile fail-closed durur.
2. Aşağıdaki salt-okunur preflight sonuçlarını kaydet.
3. `163_questions_client_dml_lockdown.sql` dosyasını tek parça uygula.
4. `164_question_revision_outcome_scope.sql` dosyasını tek parça uygula.
5. `165_question_search_admin_aal2.sql` dosyasını tek parça uygula.
6. Postflight ve gerçek rol testlerini çalıştır. Sonuçlar alınmadan soru üretimi,
   manuel ekleme veya UGC onayını yeniden açma.

## Preflight (salt okunur)

```sql
-- Composite pointer drift kesinlikle 0 olmalı.
SELECT count(*) AS cross_question_pointer_count
FROM public.questions q
JOIN public.question_content_revisions r ON r.id=q.published_revision_id
WHERE r.question_id<>q.id;

-- Migration 163 öncesi bütün açık DML grantee'lerini kanıt olarak sakla.
SELECT grantee,privilege_type
FROM information_schema.role_table_grants
WHERE table_schema='public' AND table_name='questions'
  AND privilege_type IN ('INSERT','UPDATE','DELETE')
ORDER BY grantee,privilege_type;

SELECT policyname,cmd,roles,qual,with_check
FROM pg_policies
WHERE schemaname='public' AND tablename='questions'
  AND cmd IN ('INSERT','UPDATE','DELETE','ALL')
ORDER BY policyname;

-- FK doğrulama/lock süresini yorumlamak için tablo boyutları.
SELECT
  (SELECT count(*) FROM public.questions) AS questions,
  (SELECT count(*) FROM public.question_content_revisions) AS revisions,
  (SELECT count(*) FROM public.question_revision_outcomes) AS revision_outcomes;

-- Uzun süren yazıcı varsa migration penceresinden önce bitir.
SELECT pid,usename,state,wait_event_type,wait_event,query_start,left(query,200) AS query
FROM pg_stat_activity
WHERE datname=current_database() AND state<>'idle'
  AND query ~* '(insert|update|delete).*questions';
```

`cross_question_pointer_count>0`, beklenmeyen özel DML rolü veya uzun writer
varsa dur. Veri düzeltmesini ayrı, incelenebilir bir forward migration olarak yap.

## Postflight

```sql
SELECT
  has_table_privilege('anon','public.questions','UPDATE') AS anon_update,
  has_table_privilege('authenticated','public.questions','UPDATE') AS authenticated_update,
  has_table_privilege('service_role','public.questions','UPDATE') AS service_update,
  has_column_privilege('authenticated','public.questions','id','SELECT') AS authenticated_id_read,
  has_column_privilege('authenticated','public.questions','content','SELECT') AS authenticated_content_read;
-- Beklenen: false, false, false, true, false.

SELECT p.oid::regprocedure AS writer,owner_role.rolname AS owner,p.prosecdef,p.proconfig
FROM pg_proc p
JOIN pg_roles owner_role ON owner_role.oid=p.proowner
WHERE p.oid IN (
  'public.create_governed_question(uuid,jsonb,uuid)'::regprocedure,
  'public.publish_question_content_revision(uuid,uuid,uuid)'::regprocedure,
  'public.quarantine_question_content(uuid,uuid,text,uuid)'::regprocedure
)
ORDER BY writer;
-- Üçü de trusted DB owner, prosecdef=true, search_path=pg_catalog olmalı.

SELECT
  has_function_privilege('authenticated','public.create_governed_question(uuid,jsonb,uuid)','EXECUTE') AS client_create,
  has_function_privilege('authenticated','public.publish_question_content_revision(uuid,uuid,uuid)','EXECUTE') AS client_publish,
  has_function_privilege('authenticated','public.quarantine_question_content(uuid,uuid,text,uuid)','EXECUTE') AS client_quarantine,
  has_function_privilege('service_role','public.create_governed_question(uuid,jsonb,uuid)','EXECUTE') AS server_create,
  has_function_privilege('service_role','public.publish_question_content_revision(uuid,uuid,uuid)','EXECUTE') AS server_publish,
  has_function_privilege('service_role','public.quarantine_question_content(uuid,uuid,text,uuid)','EXECUTE') AS server_quarantine;
-- Beklenen: false, false, false, true, true, true.

SELECT conname,convalidated
FROM pg_constraint
WHERE conrelid='public.questions'::regclass
  AND conname='questions_published_revision_question_fkey';
-- Beklenen: tek satır, convalidated=true.

SELECT count(*) AS client_write_policy_count
FROM pg_policies
WHERE schemaname='public' AND tablename='questions'
  AND cmd IN ('INSERT','UPDATE','DELETE','ALL');
-- Beklenen: 0.
```

Ardından:

- AAL1 ve AAL2 kullanıcı JWT'leriyle doğrudan PostgREST `questions` UPDATE dene;
  ikisi de `42501` almalı.
- AAL1 admin JWT ile `search_questions(admin_view=true)` dene; `42501` almalı.
  Aynı çağrı AAL2 admin JWT ile ham içeriği döndürmeli; `admin_view=false` her
  iki seviyede de answer/solution alanlarını kırpmalı.
- Aynı oturumda `questions.id` okunmalı, `questions.content` okunmamalı.
- `/api/questions` legacy PATCH, admin için de `409 CONTENT_GOVERNANCE_REQUIRED`
  dönmeli.
- Yönetilen taslak oluştur, Stage 1 onayla, kazanımı değiştir: durum yeniden
  `draft` olmalı ve eski Stage 1 onayı silinmeli.
- Yeni Stage 1 + bağımsız Stage 2 + publish smoke'u başarılı olmalı.
- `get_question_outcome_coverage` RPC sonucunu kaydet; sayıların iyileşmesi insan
  eşlemesiyle ölçülür, toplu otomatik kazanım ataması yapılmaz.

## Geri dönüş

Eski browser/service-role DML grantlerini geri vermek güvenli rollback değildir.
Bir hata olursa üretim/UGC yazma uçlarını kapalı tut, problemi yeni bir forward
migration ile düzelt. Tarihsel `database/*.mjs` direct-DML betikleri migration 163
sonrasında servis anahtarıyla bilinçli olarak çalışmaz; break-glass yalnız owner
yetkili, kayda alınmış ve incelenmiş SQL migration'ıdır.
