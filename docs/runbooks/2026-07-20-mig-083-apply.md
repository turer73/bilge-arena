# Migration 083 Apply Runbook

**Migration:** `database/migrations/083_wrong_answers_partial_index.sql`
**Amaç:** `session_answers(user_id, answered_at) WHERE is_correct=false` partial index — konu#7 (Faz-2) kararına dahil, opsiyonel performans katkısı. `/api/review/wrong-answers` ve `questions/random`'daki FSRS-aday-taraması aynı filtre desenini (`user_id=? AND is_correct=false ORDER BY answered_at`) kullanıyor; index bu iki sorgu için de geçerli.
**Risk:** DÜŞÜK — yalnız yeni bir index ekliyor, mevcut fonksiyon/trigger/RPC'ye dokunmuyor. Tek dikkat noktası: `CREATE INDEX` (`CONCURRENTLY` değil, bu repo'nun migration-transaction konvansiyonu gereği) `session_answers` büyükse kısa süreli yazma-kilidi oluşturabilir.
**Geri alma:** `DROP INDEX IF EXISTS idx_answers_user_wrong_time;` — sıfır veri riski, saf performans geri-alımı.

## Ön koşul kontrol listesi

- [x] Migration lint: 86 migration temiz

## Apply

Supabase Dashboard → SQL Editor:

```sql
BEGIN;

CREATE INDEX IF NOT EXISTS idx_answers_user_wrong_time
  ON public.session_answers (user_id, answered_at)
  WHERE is_correct = false;

COMMIT;
```

## Post-apply doğrulama

```sql
SELECT indexname FROM pg_indexes
WHERE tablename = 'session_answers' AND indexname = 'idx_answers_user_wrong_time';
```

Beklenen: 1 satır. Fonksiyonel doğrulama gerekmiyor (yalnız index, davranış değişmiyor) — `/arena/yanlislarim` sayfasının hâlâ normal yüklendiğini görmek yeterli.
