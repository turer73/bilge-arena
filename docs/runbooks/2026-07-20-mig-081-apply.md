# Migration 081 Apply Runbook

**Migration:** `database/migrations/081_atomic_complete_game_session.sql`
**Amaç:** Oturum-tamamlama akışını (session+answers+question-stats+coin+XP+topic-progress) tek atomik `complete_game_session` RPC'sine taşımak — kısmi hata artık tutarsız ödül durumuna yol açmaz. Idempotency (`client_request_id`) network-retry'de yeniden ödül üretimini engeller.
**Risk:** YÜKSEK — bu migration + eşlik eden kod değişikliği (`ea9f72c`, master'da zaten canlı) **her quiz oturumunun** ödül-yolu. Migration uygulanmadan `complete_game_session` fonksiyonu yoktur; kod zaten bu fonksiyonu çağırıyor, yani **migration uygulanana kadar `/api/sessions` POST'u herkes için 500 döner (oturum kaydedilemez)**. Bu, mig-049/080'den farklı bir sıralama riski: kod ÖNCE deploy oldu (Vercel, merge ile otomatik), migration SONRA elle uygulanacak — bu pencere boyunca kullanıcılar oturum kaydedemez.
**Geri alma:** Migration dosyasının sonunda hazır (fonksiyon + kolonu kaldırır) — AMA route.ts zaten yeni RPC'yi çağırıyor, rollback yapılırsa route.ts'in de eski koda döndürülmesi (ayrı commit, `ea9f72c`'den önceki hale) gerekir, aksi halde rollback sonrası oturum kaydetme YİNE kırılır.

## ÖNEMLİ — Apply penceresi

## Geri alma (rollback)

Yalnız smoke-test kritik şekilde kırılırsa ve HIZLI bir code-revert mümkün değilse:

```sql
BEGIN;
DROP FUNCTION IF EXISTS public.complete_game_session(
  UUID, UUID, TEXT, TEXT, TEXT, SMALLINT, JSONB, INTEGER, INTEGER, INTEGER,
  SMALLINT, SMALLINT, INTEGER, NUMERIC
);
ALTER TABLE public.game_sessions DROP COLUMN IF EXISTS client_request_id;
COMMIT;
```

**UYARI:** Bu rollback route.ts'i eski koda döndürmez — route.ts hâlâ `complete_game_session`'ı çağıracağı için rollback SONRASI `/api/sessions` YİNE 500 döner. Gerçek rollback için Vercel'de `ea9f72c` öncesi bir deploy'a dönmek (`git revert` + push) GEREKİR. Bu yüzden rollback yerine, mümkünse önce sorunu canlıda hızlıca (yeni migration/hotfix ile) düzeltmek tercih edilmeli.
