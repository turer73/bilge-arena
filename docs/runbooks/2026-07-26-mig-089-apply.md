# Migration 089 Apply Runbook

**Migration:** `database/migrations/089_fix_handle_new_user_long_email.sql`

## Purpose and order

Migration 089 fixes GoTrue `unexpected_failure` caused by SQLSTATE `22001` in `public.handle_new_user()`: a long email local-part was assigned to `VARCHAR(32)` before it was shortened.

Apply this database migration before retrying admin user creation or promoting any workflow that depends on the auth-create smoke test. It replaces only the trigger function body; it does not drop or recreate the existing `auth.users` trigger.

## Preflight

1. Run the rollback-only diagnostic in Supabase SQL Editor:

   ```sql
   -- Paste database/diagnose-auth-create-user.sql exactly.
   ```

   Expected before the fix: SQLSTATE `22001` and context mentioning `handle_new_user`.

2. Confirm the existing trigger is present:

   ```sql
   SELECT tgname, pg_get_triggerdef(oid)
   FROM pg_trigger
   WHERE tgrelid = 'auth.users'::regclass AND NOT tgisinternal;
   ```

3. Run `node database/lint-migrations.mjs` locally.

## Apply

In Supabase SQL Editor, paste `database/migrations/089_fix_handle_new_user_long_email.sql` exactly, including `BEGIN` and `COMMIT`, then run it. Do not alter or drop `on_auth_user_created` or `block_disposable_email_trg`.

## Post-check

```sql
SELECT pg_get_functiondef('public.handle_new_user()'::regprocedure);
```

Expected: `SECURITY DEFINER`, `SET search_path = ''`, `v_email_local_part TEXT`, `INSERT INTO public.profiles`, bounded retry logic, and no trigger DDL.

Run the rollback-only diagnostic again. Expected result is SQLSTATE `P0001` with `DIAGNOSTIC_INSERT_SUCCEEDED_AND_WAS_ROLLED_BACK`, proving the trigger chain completed and the diagnostic left no auth/profile row.

## Opt-in production smoke

The smoke creates one unique synthetic auth user with a long local-part and a name longer than 64 characters. It checks the generated profile, then deletes only that profile and deletes the same auth user. It never queries or changes a real user.

```powershell
$env:ALLOW_PROD_AUTH_CREATE_SMOKE = 'I_UNDERSTAND_PROD_WRITE'
node database/smoke-auth-create-user-trigger.mjs
Remove-Item Env:ALLOW_PROD_AUTH_CREATE_SMOKE
```

Expected: `PASS`, a username no longer than 32 characters, a display name truncated to 64 characters, an 8-character referral code, and no cleanup error.

## Rollback

Do not restore the old `VARCHAR(32)` pre-truncation assignment. If a regression is found, stop the create-user workflow and ship a forward migration after preserving the trigger. The diagnostic is rollback-only by design and must remain unchanged.
